# Plan: Gradle Version Management & Release APK Signing

## Problem Analysis

### Gradle Version Bloat (~50GB ~/.gradle)

- **Cause**: Each Tauri project generates its own `gradle/wrapper/gradle-wrapper.properties` with a specific Gradle version
- **Current**: Gradle 8.14.5 in `src-tauri/gen/android/gradle/wrapper/gradle-wrapper.properties`
- **Tauri plugins**: Dependencies from `~/.cargo/registry/src/.../tauri-*/mobile/android` each have their own Gradle setup
- **Result**: Multiple Gradle distributions cached in `~/.gradle/wrapper/dists/`

### Release Signing Issue

- **Current**: `build.gradle.kts` uses debug keystore (`~/.android/debug.keystore`) for **both** debug and release builds
- **Problem**: Release APK not properly signed for Play Store / distribution
- **Need**: Proper release keystore with separate alias/password

## Proposed Solutions

### Option A: Unified Gradle Wrapper (Recommended)

**Strategy**: Use a **single shared Gradle wrapper** for all Tauri Android projects

```bash
# Create shared wrapper location (e.g., project root)
mkdir -p .shared-gradle/wrapper
# Copy current wrapper there
cp src-tauri/gen/android/gradle/wrapper/gradle-wrapper.properties .shared-gradle/wrapper/
cp src-tauri/gen/android/gradlew* .shared-gradle/
```

Then configure each generated project to use the shared wrapper via `gradle.properties`:

```properties
# In each project's gradle.properties (or via init script)
gradle.user.home = .shared-gradle
```

**Pros**: Single Gradle download, ~200MB total
**Cons**: Requires modifying generated Tauri files (they're autogenerated)

### Option B: Gradle Daemon + Cache Cleanup (Easier)

**Strategy**: Keep current setup but add automation

1. **Enable Gradle configuration cache** (build.gradle.kts):

   ```kotlin
   // settings.gradle
   enableFeaturePreview("CONFIGURATION_CACHE")
   ```

2. **Add periodic cleanup script** (run monthly):

   ```bash
   # Keep only last 3 Gradle versions
   find ~/.gradle/wrapper/dists -maxdepth 2 -type d -name "gradle-*" | sort -V | head -n -3 | xargs rm -rf
   ```

3. **Use `--no-daemon` for CI** to avoid daemon accumulation

**Pros**: No changes to generated files
**Cons**: Still multiple versions, requires manual cleanup

### Option C: Fixed Gradle Version via Tauri Config (Best for Tauri)

**Strategy**: Pin Gradle version in `tauri.conf.json` so Tauri always generates the same version

```json
// tauri.conf.json
{
	"build": {
		"beforeBuildCommand": "bun run build"
	},
	"tauri": {
		"android": {
			"gradleVersion": "8.14.5",
			"agpVersion": "8.13.2"
		}
	}
}
```

**Note**: Tauri 2.x may not support this directly. Check Tauri docs.

## Release Signing Setup

### Step 1: Generate Release Keystore

```bash
# One-time setup - store securely!
keytool -genkeypair -v \
  -keystore ai-radio-release.keystore \
  -alias airadio \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -storepass <STRONG_PASSWORD> \
  -keypass <STRONG_PASSWORD> \
  -dname "CN=AI Radio, OU=Development, O=AI Radio, L=City, S=State, C=DE"
```

### Step 2: Store Credentials Securely

**Option A: Environment variables (CI/CD)**

```bash
export KEYSTORE_PASSWORD=<password>
export KEY_ALIAS=airadio
export KEY_PASSWORD=<password>
```

**Option B: Local `local.properties` (not committed)**

```properties
# src-tauri/gen/android/local.properties
keystore.path = ../ai-radio-release.keystore
keystore.password = <password>
key.alias = airadio
key.password = <password>
```

### Step 3: Update build.gradle.kts

```kotlin
// In android { signingConfigs { ... } }
val keystorePath = System.getenv("KEYSTORE_PATH")
    ?: project.property("keystore.path") as String?
    ?: return@create

val keystorePassword = System.getenv("KEYSTORE_PASSWORD")
    ?: project.property("keystore.password") as String?
    ?: return@create

create("release") {
    storeFile = file(keystorePath)
    storePassword = keystorePassword
    keyAlias = System.getenv("KEY_ALIAS") ?: project.property("key.alias") as String
    keyPassword = System.getenv("KEY_PASSWORD") ?: project.property("key.password") as String
}
```

### Phase 2: Gradle Version Management (Medium Priority)

**Choice depends on your workflow:**

| If you...                         | Choose                                |
| --------------------------------- | ------------------------------------- |
| Only build this one Tauri project | Option B (cleanup script)             |
| Have multiple Tauri projects      | Option A (shared wrapper)             |
| Want Tauri to handle it           | Option C (check Tauri config support) |

**My recommendation**: **Option B + shared Gradle user home**

- Set `GRADLE_USER_HOME=D:/gradle-cache` (dedicated disk, not ~/.gradle)
- Add cleanup script to `package.json`:
  ```json
  "scripts": {
    "gradle:clean": "powershell -Command \"Get-ChildItem D:/gradle-cache/wrapper/dists -Directory | Sort-Object Name -Descending | Select-Object -Skip 3 | Remove-Item -Recurse -Force\""
  }
  ```
